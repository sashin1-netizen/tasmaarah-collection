# Tasmaarah Collection — Client Handover

## Status

**CLIENT APPROVAL PENDING — DESIGN FREEZE ACTIVE**

The current production build is frozen for client review. No further visual, structural or interaction changes should be made unless they address explicit client feedback or a confirmed production defect.

## Production scope

The live site includes Home, About, Collection, Occasions, Custom Orders, Gallery, Contact, Privacy & Cookies and a custom 404 page.

Core conversion journey: inspiration → choose presentation/occasion → personalised quote → WhatsApp.

## Client-facing functionality

- Responsive desktop, tablet and mobile navigation with a native no-JavaScript fallback.
- Approved Tasmaarah campaign artwork protected as the homepage hero.
- Automatic decorative motion with operating-system reduced-motion support; no client-facing motion toggle.
- Collection search with live result counts.
- Occasion and Collection links prefill relevant quote details.
- Quote form composes a structured WhatsApp enquiry.
- Gallery lightbox supports keyboard, touch/swipe and contextual “Ask about this look” enquiries.
- Direct telephone, email, Instagram and WhatsApp actions.
- Official Instagram: `@boxes_tasmaarah_collection`.
- Privacy & Cookies information and a lightweight notice with no advertising or analytics tracking currently enabled.
- Courier and Reservoir Hills location information throughout the journey.
- Custom 404 recovery page.

## Quality and accessibility

- Responsive browser acceptance projects cover 360, 390, 430, 768, 1024, 1366 and 1920 widths.
- Horizontal overflow and runtime-error checks on public pages.
- One H1 per page, image-alt checks, keyboard menu and gallery controls, focus visibility and reduced-motion behaviour.
- Minimum standalone control sizes hardened for touch use.
- Visual acceptance evidence is generated by CI.
- Final release gate validates required production files, local links, sitemap coverage, JavaScript syntax and interaction contracts.

## Search, privacy and sharing

- Unique page titles and descriptions.
- Canonical URLs.
- `robots.txt` and XML sitemap, including Privacy & Cookies.
- LocalBusiness structured data on the homepage.
- Open Graph sharing metadata and campaign preview image.
- Content Security Policy on the client-facing homepage and Privacy page as an additional browser-side defence layer.
- External Instagram and WhatsApp links use safe new-tab relationship attributes where applicable.

## Launch dependency outside the codebase

The repository currently has no `CNAME` file. A branded custom domain must be supplied/configured in GitHub Pages before final public launch if the client should not use the `github.io` address. Configure the domain in **Repository Settings → Pages**, verify the domain, update DNS, then enable **Enforce HTTPS** when GitHub makes it available.

After the final domain is known, replace the current `github.io` canonical, Open Graph and sitemap URLs with the branded domain and submit the sitemap in Google Search Console.

## Approval procedure

If the client approves the current build, do not redesign. Move directly to domain/launch configuration and final deployment verification.

If the client requests changes, record each requested amendment as an acceptance item, make only those targeted changes, rerun the production quality gate and re-present the corrected build for approval.
